6. IF THE RUN IS STUCK (seen 4 Oct)
 - Symptom: sits at "2/5 API searchability" for many minutes.
 - Cause: laptop cannot reach LocoHub (internal 10.x addresses) = VPN / network dropped.
 - Check (prints True when OK):
      powershell -Command "(Test-NetConnection production.locohub-prod.aws.raileurope.com -Port 443).TcpTestSucceeded"
 - Fix: reconnect VPN, press Ctrl+C in the run window (answer Y), then rerun npm run sanity.
 - Check nothing is left running:
      tasklist /FI "IMAGENAME eq node.exe"
 - Kill a leftover run completely (/T = whole process tree):
      taskkill /F /T /PID <number>
 - A killed or Ctrl+C run does not send Slack/mail. Booking refs it created stay valid,
   but a rerun creates new ones - use the NEW refs.

8. WHAT THE RESULTS MEAN
 - Mail subject: OK / KO. KO = an automated item failed OR the booking suite did not
   capture a booking ref.
 - "[check manually]" = the run could not verify it (login expired, tool not set up).
 - Connectivity carriers flagged >15 min are listed for your review. Not a failure.
 - A sector is only DROPPED/ERROR after the primary route AND all backup routes failed.
 - Cart order looks jumbled (#1,#3,#5... then #2,#4...): flagged carriers are built last
   on purpose.
 - Portal lines (4-7) log in and SEARCH; a sign-in page alone no longer counts as OK.
   A KO there names the error the page showed. Slow suggestions are retried once.
   If you see a KO, check that portal by hand and tell Claude.
 - Point 1 reads OK when B2B was proven by the booking run, even if the B2C API half could
   not run (then it is listed under "still to check" in the console).
 - Point 1 showing [check manually] / API not run: look at report\api-searchability.json. If it
   says "envs": [] the Postman folder was not found. Expected folder:
   C:\Users\PSalgaonkar\OneDrive - RAILEUROPE\Desktop\Training Material\Postman Collections\LH
