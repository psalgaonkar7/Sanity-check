0. GOLDEN RULES
 - Run ONE sanity at a time (shared B2B login, cart, POS). Two at once corrupt each other.
 - It never pays. It stops at Traveler Details and captures booking refs (K + 9 digits;
   the China booking ref starts with Z).
 - Open CMD and always start with:   cd C:\Claude\RE\ASC
 - While the Pratikesh Assistant runs LIVE, it owns sanity (since 2026-10-26): it runs
   "npm run sanity" here by itself at the round hours, ready BY the hour (starts 10 min
   before, e.g. 07:50 for the 08:00 slot, then every 2h), in its own "ASC sanity" window;
   the mail and DM say the round hour. Don't start one by hand then - use the dashboard's
   "Run sanity now" button (http://localhost:4546) instead.
   See RE\Assistant\CMD-cheatsheet.txt.

1. DAILY ROUTINE
 a) Log in (about once a day, all in cmd, no browser window opened by the tool):
      cd C:\Claude\RE\ASC
      npm run auth
    (the same command as  npm run auth:all) It signs in only what is expired:
    - the 5 portals (B2B ROW, Key account ROW, Agents ROW, Key account China, Customer care
      China) with ONE username + password typed here (hidden, never saved);
    - AWS EU, then AWS China: your browser opens by itself (old style): click Allow there.
      (AWS signs in through the company page, so no password is typed here for it.)
    - Skipping AWS makes the Group Bookings-Salesforce Sync and Dropfile sanity check items
      read [check manually].
    - One AWS login (sso-session "era") covers both AWS profiles the sanity run uses:
      era-prod (AppFlow) and ariane-prod (dropfile).
 b) Run the sanity check (about 7 min; up to ~14 min on days a carrier's search times out):
      cd C:\Claude\RE\ASC
      npm run sanity
    - Needs the VPN / corporate network connected (API step reaches LocoHub).
    - Last step opens the Outlook draft and sends YOU the result as a Slack DM (Pratikesh
      Assistant chat). Nothing is posted to the team channel any more. For a complete run the
      DM holds the "Sanity done HH:MM IST- K..." line, ready to paste in the team channel.
      A KO run is DMed too, with the reason (and says not to post "Sanity done").
    - The mail ends with the Sanity Tracker link. Points 3-6 (key account ROW, agents ROW,
      key account China, customer care China) are OK only after a logged-in search worked.
      Customer care China also books 1 train (stops at Traveler Details, never pays).
    - Booking refs are NOT in the subject: point 1 has the customer care ROW refs, point 6 the
      China ref, e.g.  "Customer care china working :- OK (Booking ref: K123456789)".
      If one says [check manually] its saved login expired: run  npm run auth:portals
    - Paste the email body (Ctrl+V), review, press Send yourself.
    - The mail has 10 points, each OK, KO or [check manually]  (the "B2B System Connectivity
      Status" point was removed on 2026-10-28, so everything after point 1 moved up by one):
        1 B2C & B2B check (customer care ROW booking refs)   2 Group Bookings-Salesforce Sync
        3 Key account ROW   4 Agents portal ROW   5 Key account China
        6 Customer care China (China booking ref, Z...)   7 SNCF   8 Primer
        9 Dropfile sanity check   10 SF cases (shows 0 until Salesforce is approved)
 c) By hand each run (the tool cannot do these):
      - Slack #ariane-alerts-prod: any failed Glue job? If yes raise a Jira SR for the
        third-party team. (Procedure: Confluence SR page 2223472642; recording in
        #team-application-support)
      - SF case count (point 10)
      - Any carrier listed as DROPPED in the run's summary (e.g. RegioJet): the mail line
        does not turn KO for that on its own, so look at it yourself

6. IF THE RUN IS STUCK (seen 4 Oct)
 - Symptom: sits at "2/5 API searchability" for many minutes.
 - Cause: laptop cannot reach LocoHub (internal 10.x addresses) = VPN / network dropped.
 - Check (prints True when OK):
      powershell -Command "(Test-NetConnection production.locohub-prod.aws.raileurope.com -Port 443).TcpTestSucceeded"
 - Fix: reconnect VPN, press Ctrl+C in the run window (answer Y), then rerun npm run sanity.
 - Check nothing is left running:
      tasklist /FI "IMAGENAME eq node.exe"
 - Kill a leftover run completely (/T = whole process tree):
      taskkill /F /T /PID <number>
 - A killed or Ctrl+C run does not send the DM/mail. Booking refs it created stay valid,
   but a rerun creates new ones - use the NEW refs.

8. WHAT THE RESULTS MEAN
 - Mail subject: OK / KO. KO = an automated item failed OR the booking suite did not
   capture a booking ref.
 - "[check manually]" = the run could not verify it (login expired, tool not set up).
 - The carrier-connectivity page and LocoHub staging are NOT part of the sanity any more
   (removed 2026-10-28): no mail point, no KO from them.
 - A sector is only DROPPED/ERROR after the primary route AND all backup routes failed.
   A dropped carrier (e.g. RegioJet) is in the run summary only: it does not turn a mail
   line KO by itself, so look at it yourself.
 - The run no longer reads the connectivity page, so the cart order is now simply the list
   order (no carriers are moved to the end any more).
 - China KO with title "Loading | Rail Europe": portal slow to boot. Wait is now 120s.
   If you see it again, check the portal by hand and tell Claude.
 - Point 1 reads OK when B2B was proven by the booking run, even if the B2C API half could
   not run (then it is listed under "still to check" in the console).
 - Point 1 showing [check manually] / API not run: look at report\api-searchability.json. If it
   says "envs": [] the Postman folder was not found. Expected folder:
   %USERPROFILE%\OneDrive - RAILEUROPE\Desktop\Training Material\Postman Collections\LH
   (your own user folder; or point POSTMAN_DIR at wherever your exports are)
   (or set POSTMAN_DIR).
